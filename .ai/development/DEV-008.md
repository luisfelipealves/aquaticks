# Complication startup availability

Direct bug report authorizes a bounded native correction. User confirms reminders work in0.2.5; preserve their schedule, stable signer and data. Earlier automatic return after many minutes, latest reboot still blank; provider selection loss vs delayed delivery remains unproven. No watch logs available.

Investigation: same provider component name retained; exported service and permission/types valid; no provider configuration activity. Missing directBootAware means unavailable to pre-unlock requests. Provider unconditionally accesses credential-encrypted Room. Official AndroidX ComplicationDataSourceService recommends direct boot availability since AndroidT; Android Direct Boot guide requires guarding credential storage with UserManager.isUserUnlocked. Existing BOOT_COMPLETED receiver refreshes surfaces after unlocking. This is a demonstrated startup compatibility defect, not proven Samsung host root cause.

Scope: direct-boot-aware existing service; no Room access while locked; native NoData response before unlock; normal timeline/data after unlock; fixed-size device-protected local lifecycle/request diagnostic visible in settings to distinguish no request, locked, delivered, failure and deactivation. Keep histories only in Room, no duplicate hydration cache. No dependency, polling, permanent service, DB migration, reset, scheduling change, renamed provider or main merge. Release0.2.6/code8.
